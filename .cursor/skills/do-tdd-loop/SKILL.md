# TDD-цикл

## Чеклист

- [ ] 1. Прочитать утверждённую спецификацию, task graph и критерии приёмки.
- [ ] 2. Проверить текущую ветку или worktree и определить первый вертикальный срез.
- [ ] 3. Написать один минимальный тест на публичное поведение из критериев приёмки.
- [ ] 4. Запустить релевантный тест и зафиксировать ожидаемый статус **RED**.
- [ ] 5. Написать минимальную реализацию без speculative features.
- [ ] 6. Запустить тест повторно и получить **GREEN**.
- [ ] 7. Прочитать ошибки при падении, исправить причину и повторить цикл.
- [ ] 8. Повторить шаги 3–7 для следующих вертикальных срезов.
- [ ] 9. Запустить полный набор тестов, линтеры и другие проверки проекта.
- [ ] 10. Сопоставить результаты с каждым критерием приёмки и подготовить отчёт.

## Правила

- Тестируй публичные интерфейсы, а не детали реализации.
- Не подменяй RED искусственным падением: тест должен проверять отсутствующее поведение.
- Не изменяй тест только для получения GREEN без доказательства ошибки в контракте.
- Рефакторинг выполняй после GREEN и снова запускай затронутые проверки.
- При незелёных проверках задача не считается завершённой.
