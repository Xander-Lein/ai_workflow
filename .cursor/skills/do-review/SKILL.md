# Review и валидация

## Чеклист

- [ ] 1. Определить фиксированную точку, head и полный diff для ревью.
- [ ] 2. Прочитать спецификацию, критерии приёмки и правила репозитория.
- [ ] 3. Проверить, что изменённые контракты не ломают существующие callers и сценарии.
- [ ] 4. Провести review по требованиям: полнота, корректность, регрессии и обработка ошибок.
- [ ] 5. Провести review по стандартам: структура, читаемость, дублирование, лишняя сложность и безопасность.
- [ ] 6. Запустить `python scripts/check.py` для проверки skills, ссылок, metadata и секретов.
- [ ] 7. Запустить релевантные тесты, линтеры и проверки проекта.
- [ ] 8. Для каждого finding указать severity, файл, доказательство и исправление.
- [ ] 9. Исправить блокирующие findings и повторить затронутые проверки.
- [ ] 10. Сформировать итог: findings по требованиям, findings по стандартам, проверки и ограничения.

## Правила

- Не смешивай findings по требованиям и стандартам.
- Не объявляй review успешным без фактического запуска доступных проверок.
- Отдельно указывай отсутствующую спецификацию, неполные тесты или невозможность проверки.
- `scripts/check.py` валидирует сам набор, но не заменяет тесты приложения.
